## 🤖 Asistente (Antigravity)

Es una muy buena pregunta. Instalar paquetes de forma global tiene la ventaja de la comodidad, pero en el mundo de Python suele desaconsejarse (y en tu caso particular, tiene un riesgo extra) por los siguientes motivos:

### 1. El Python que estamos usando es de Anki
El intérprete de Python que hemos encontrado en tu ordenador está dentro de la carpeta de **Anki** (`AppData\Local\AnkiProgramFiles`). Si instalamos librerías pesadas (como `librosa`, `scipy`, `av`) directamente en su carpeta global:
*   Podríamos interferir con el funcionamiento de Anki si alguna librería entra en conflicto.
*   Si actualizas Anki, es muy probable que esa instalación de Python se borre o se reinstale desde cero, perdiendo todas las librerías instaladas.

### 2. Conflictos de versiones (Dependency Hell)
Las librerías de audio y machine learning cambian muy rápido. Si en el futuro otro proyecto necesita una versión más antigua de `numpy` o de `scipy` (por ejemplo, para usar TensorFlow), e intentas instalarla globalmente, romperás este proyecto de transcripción. Los entornos virtuales (`.venv`) aíslan cada proyecto para que nunca se rompan entre sí.

Si no quieres crear un entorno virtual para cada canción o proyecto musical, lo ideal no es instalarlo de manera 100% global, sino **crear un único entorno virtual compartido** para tus herramientas de música.
